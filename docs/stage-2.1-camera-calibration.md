# Stage 2.1 — метрическое определение формата по калиброванной камере

## Зачем нужна калибровка

Форматы C6, C5, C4 и B4 имеют близкое отношение сторон. Поэтому после обычного perspective rectification нельзя надёжно отличить их только по `width_px / height_px`: абсолютный масштаб теряется.

В сортировщике камера фиксирована, а письмо находится в одной рабочей плоскости транспортёра. Это позволяет построить projective homography из координат изображения в миллиметры плоскости транспортёра.

После калибровки формат определяется по фактическим физическим размерам ГОСТ:

| Формат | Ширина, мм | Высота, мм |
|---|---:|---:|
| C6 | 162 | 114 |
| DL | 220 | 110 |
| C5 | 229 | 162 |
| C4 | 324 | 229 |
| B4 | 353 | 250 |

Таким образом C4, C5 и B4 различаются прежде всего метрически, а не по отношению сторон.

## Набор калибровок по эталонным форматам

Начиная с версии 2 формата файла `camera-calibration.json` в одном файле хранятся независимые калибровочные записи для нескольких эталонных форматов.

Пример:

```json
{
  "version": 2,
  "standard": "ГОСТ Р 51506-99",
  "calibrations": {
    "C5": {
      "version": 1,
      "standard": "ГОСТ Р 51506-99",
      "reference_format": "C5",
      "reference_width_mm": 229.0,
      "reference_height_mm": 162.0,
      "image_width_px": 3732,
      "image_height_px": 2888,
      "image_aspect_ratio": 1.292243767,
      "homography_norm_to_mm": [[...], [...], [...]]
    },
    "DL": {
      "version": 1,
      "standard": "ГОСТ Р 51506-99",
      "reference_format": "DL",
      "reference_width_mm": 220.0,
      "reference_height_mm": 110.0,
      "image_width_px": 3732,
      "image_height_px": 2888,
      "image_aspect_ratio": 1.292243767,
      "homography_norm_to_mm": [[...], [...], [...]]
    }
  }
}
```

Верхний `version: 2` относится к контейнеру набора. Каждая отдельная калибровочная запись пока имеет `version: 1`.

## Калибровка камеры

Под камеру помещается полностью видимый эталон известного формата.

Требования:

1. камера, объектив, zoom/crop и положение транспортёра должны соответствовать production;
2. эталон лежит в той же плоскости, что и обычные письма;
3. видны все четыре физические границы;
4. длинная сторона примерно горизонтальна;
5. эталон не должен быть согнут или заметно деформирован.

Пример первой калибровки C5:

```bash
make layout-calibrate \
  FILE=/path/reference-c5.jpg \
  FORMAT=C5
```

После этого можно добавить DL:

```bash
make layout-calibrate \
  FILE=/path/reference-dl.jpg \
  FORMAT=DL
```

Вторая команда **не удаляет C5**. Она обновляет только `calibrations.DL`.

Повторная команда с `FORMAT=C5` заменяет только запись `calibrations.C5`, сохраняя DL/C4/B4/C6.

Просмотреть текущий набор:

```bash
make layout-calibrations
```

Ожидаемый вывод:

```json
{
  "version": 2,
  "standard": "ГОСТ Р 51506-99",
  "count": 2,
  "formats": [
    "C5",
    "DL"
  ]
}
```

По умолчанию файл находится в:

```text
config/camera-calibration.json
```

Файл не коммитится в Git, потому что относится к конкретной камере.

## Автоматическая миграция старого файла

Старый одноформатный файл версии 1 по-прежнему читается сервисом.

При следующем запуске:

```bash
make layout-calibrate FILE=/path/new-reference.jpg FORMAT=<FORMAT>
```

Makefile автоматически преобразует старый файл в контейнер `version: 2`, сохраняя старую запись и добавляя/обновляя новую.

Если старый файл уже был перезаписан до обновления Stage 2.1, ранее потерянную калибровку восстановить автоматически нельзя: соответствующий эталон нужно откалибровать повторно.

## Как используется несколько калибровок

Физический формат production-письма заранее неизвестен, поэтому нельзя выбирать калибровку по предполагаемому формату — это создало бы циклическую зависимость.

ToolOCR применяет все доступные калибровки к одному и тому же найденному внешнему четырёхугольнику. Каждая запись независимо даёт оценку размеров в миллиметрах. Затем берётся robust consensus по медиане.

Пример структуры ответа:

```json
{
  "metric_format": {
    "calibration": {
      "status": "loaded",
      "count": 2,
      "reference_formats": ["C5", "DL"]
    },
    "consensus": {
      "consistent": true,
      "reference_formats": ["C5", "DL"],
      "width_spread_mm": 2.1,
      "height_spread_mm": 1.4,
      "measurement": {
        "width_mm": 229.8,
        "height_mm": 161.5
      },
      "per_reference": [
        {
          "reference_format": "C5",
          "measurement": {"width_mm": 228.9, "height_mm": 162.0}
        },
        {
          "reference_format": "DL",
          "measurement": {"width_mm": 231.0, "height_mm": 160.6}
        }
      ]
    }
  }
}
```

Если разброс между эталонами превышает 12 мм по ширине или высоте, набор считается `inconsistent`, метрический формат не выбирается и система возвращается к visual profile scoring. Это защищает от случайного добавления калибровки с другим FOV, неправильным эталонным форматом или ошибочно найденным контуром.

## Что хранится в каждой записи

Основное поле:

```json
{
  "homography_norm_to_mm": [[...], [...], [...]]
}
```

Входные координаты сначала нормализуются:

```text
x_norm = x_px / image_width_px
y_norm = y_px / image_height_px
```

Поэтому калибровка переносится на другое разрешение при неизменных FOV и отношении сторон. Изменение положения камеры, оптики, crop/zoom или геометрии транспортёра требует повторной калибровки всех эталонных записей.

## Production-анализ

После появления `config/camera-calibration.json` обычный:

```bash
make layout-smoke FILE=/path/letter.jpg | jq
```

добавляет метрическое решение. Если consensus согласован и формат разрешён, visual profile scoring больше не сравнивает C4 с C5/B4. Он получает только профили найденного физического формата и решает:

```text
I / II
window / no-window
0° / 180°
```

## Partial frame

Если письмо касается верхней/нижней границы кадра, высота считается `lower_bound`, но ширина остаётся метрическим признаком. Аналогично при контакте с левой/правой границей полная высота остаётся сильным признаком, а ширина становится `lower_bound`.

Если одновременно обрезаны обе размерности, метрический confidence намеренно уменьшается и система может вернуть `ambiguous`.

## Диагностика

Полезный вывод:

```bash
make layout-smoke FILE=/path/letter.jpg \
  | jq '{
      layout_status,
      metric_format,
      format_status,
      format,
      orientation,
      profile_scoring,
      timing
    }'
```

Для контроля согласованности нескольких калибровок:

```bash
make layout-smoke FILE=/path/letter.jpg \
  | jq '.metric_format | {
      status,
      format,
      calibration,
      consensus
    }'
```

Если калибровка отсутствует или набор некорректен, ToolOCR автоматически использует visual scoring как fallback.
