# Stage 2.1 — метрическое определение формата по калиброванной камере

## Зачем нужна калибровка

Форматы C6, C5, C4 и B4 имеют близкое отношение сторон. Поэтому после обычного perspective rectification нельзя надёжно отличить их только по `width_px / height_px`: абсолютный масштаб теряется.

В сортировщике камера фиксирована, а письмо находится в одной рабочей плоскости транспортёра. Это позволяет один раз построить projective homography из координат изображения в миллиметры плоскости транспортёра.

После калибровки формат определяется по фактическим физическим размерам ГОСТ:

| Формат | Ширина, мм | Высота, мм |
|---|---:|---:|
| C6 | 162 | 114 |
| DL | 220 | 110 |
| C5 | 229 | 162 |
| C4 | 324 | 229 |
| B4 | 353 | 250 |

Таким образом C4, C5 и B4 различаются прежде всего метрически, а не по отношению сторон.

## Однократная калибровка камеры

Под камеру помещается полностью видимый эталон известного формата. Предпочтительно использовать C4 либо жёсткую калибровочную пластину соответствующего размера.

Требования:

1. камера, объектив, zoom/crop и положение транспортёра должны соответствовать production;
2. эталон лежит в той же плоскости, что и обычные письма;
3. видны все четыре физические границы;
4. длинная сторона примерно горизонтальна;
5. эталон не должен быть согнут или заметно деформирован.

После запуска OCR/layout-контейнера:

```bash
make layout-calibrate \
  FILE=/path/reference-c4.jpg \
  FORMAT=C4
```

По умолчанию создаётся:

```text
config/camera-calibration.json
```

Файл не коммитится в Git, потому что относится к конкретной камере.

Калибровочный endpoint:

```text
POST /v1/layout/calibration/estimate?known_format=C4
```

сам ничего не записывает. Make-команда извлекает поле `calibration`, проверяет JSON и сохраняет его атомарно.

## Что хранится в калибровке

Основное поле:

```json
{
  "homography_norm_to_mm": [[...], [...], [...]]
}
```

Входные координаты сначала нормализуются:

```text
x_norm = x_px / image_width_px
y_norm = y_px / image_height_px
```

Поэтому калибровка переносится на другое разрешение при неизменных FOV и отношении сторон. Изменение положения камеры, оптики, crop/zoom или геометрии транспортёра требует повторной калибровки.

## Production-анализ

После появления `config/camera-calibration.json` обычный:

```bash
make layout-smoke FILE=/path/letter.jpg | jq
```

добавляет:

```json
{
  "metric_format": {
    "status": "resolved",
    "format": "C4",
    "confidence": 0.98,
    "measurement": {
      "width_mm": 323.2,
      "height_mm": 228.5,
      "width_exact": true,
      "height_exact": true
    },
    "candidates": [
      {"format": "C4", "score": 0.99},
      {"format": "B4", "score": 0.02},
      {"format": "C5", "score": 0.0}
    ]
  },
  "format_status": "resolved_by_camera_calibration",
  "format": "C4"
}
```

Числа выше иллюстративные.

Если метрический формат разрешён, visual profile scoring больше не сравнивает C4 с C5/B4. Он получает только профили найденного физического формата и решает:

```text
I / II
window / no-window
0° / 180°
```

## Partial frame

Если письмо касается верхней/нижней границы кадра, высота считается `lower_bound`, но ширина остаётся метрическим признаком. Аналогично при контакте с левой/правой границей полная высота остаётся сильным признаком, а ширина становится `lower_bound`.

Пример для C4, обрезанного снизу:

```json
{
  "measurement": {
    "width_mm": 324.6,
    "height_mm": 205.1,
    "width_exact": true,
    "height_exact": false
  }
}
```

В таком случае C4 может быть надёжно отличён от C5/B4 по полной ширине около 324 мм, даже если высота наблюдается не полностью.

Если одновременно обрезаны обе размерности, метрический confidence намеренно уменьшается и система может вернуть `ambiguous`.

## Диагностика

Полезный вывод:

```bash
make layout-smoke FILE=/path/letter.jpg \
  | jq '{
      layout_status,
      metric_format,
      format_status,
      format,
      orientation,
      profile_scoring,
      timing
    }'
```

Если калибровка отсутствует:

```json
"metric_format": {
  "status": "unavailable",
  "calibration": {
    "status": "unavailable"
  }
}
```

и ToolOCR автоматически использует прежний visual scoring как fallback.
