# Stage 2.2 — геометрия шести ячеек индекса

## Цель

Перед подключением распознавания цифр необходимо отдельно подтвердить, что после локализации `recipient_postcode` каждая из шести цифр полностью попадает в собственную ячейку.

На этом этапе распознавание цифр не выполняется. Проверяется только геометрия.

## Источник геометрии

Ячейки не получаются делением общего bbox индекса на шесть равных частей.

Используется уже подтверждённая структура postcode stencil:

```text
[=] [1] [2] [3] [4] [5] [6]
 c0  c1  c2  c3  c4  c5  c6
```

Postcode detector уже возвращает:

```text
bar_width_px
bar_step_px
row_y_norm
```

а `detected_bbox` привязан к первой и последней найденным верхним плашкам.

Центр стартовой верхней плашки `c0` восстанавливается из левой границы `detected_bbox` и ширины плашки. Центры шести цифр получаются через регулярный `bar_step_px`.

Для каждой цифры горизонтальные границы проходят посередине между соседними anchors:

```text
cell1 = midpoint(c0,c1) .. midpoint(c1,c2)
cell2 = midpoint(c1,c2) .. midpoint(c2,c3)
...
cell6 = midpoint(c5,c6) .. c6 + step/2
```

По вертикали верх ячейки начинается ниже строки верхних плашек. Нижняя граница имеет запас относительно ожидаемой высоты цифры. Верхняя плашка в будущий digit recognizer crop не включается.

## Test UI

`GET /v1/test-ui/images/{id}/roi` дополнительно рисует шесть ячеек `D1..D6` поверх ROI preview.

Ячейки имеют отдельный цвет от оранжевой рамки postcode, чтобы визуально различать:

```text
пунктирная оранжевая рамка — postcode search zone
сплошная оранжевая рамка  — найденный postcode stencil
D1..D6                     — будущие индивидуальные digit ROI
```

## Corpus-validation

Перед реализацией recognizer нужно прогнать C4, C5 и DL и визуально проверить для каждого успешного postcode:

1. присутствуют ровно шесть ячеек;
2. ячейки идут слева направо в порядке `D1..D6`;
3. верхняя плашка не попадает внутрь digit ROI;
4. каждая цифра полностью находится внутри своей ячейки по X и Y;
5. соседняя цифра не попадает в чужую ячейку;
6. нижние штрихи цифр не обрезаются;
7. на `seven_bar_rescue` геометрия не отличается по смыслу от strict-path.

Только после этого геометрию фиксируем и подключаем специализированный recognizer 0..9.

## Regression

`tests/test_postcode_digit_cells.py` строит синтетический strict stencil с заранее известными границами шести цифр и проверяет, что каждая из них полностью содержится в соответствующей `digit_cell`. Отдельно проверяется отсутствие ячеек при `stencil_not_found`.

Orientation, strict/rescue thresholds и сам postcode detector этим этапом не изменяются.
