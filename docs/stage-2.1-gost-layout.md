# Stage 2.1 — сегментация конверта по ГОСТ Р 51506-99

## Источник геометрии

Для сегментации лицевой стороны почтового конверта используется ГОСТ Р 51506-99 «Конверты почтовые. Технические требования. Методы контроля».

В коде стандарт рассматривается как источник геометрии и вариантов оформления, а не как обучающий датасет. Полный текст ГОСТ в публичный репозиторий не включается.

Основные ссылки на стандарт:

- п. 4.1.1, таблица 1 — стандартные размеры C6, DL, C5, C4, B4;
- п. 4.1.4 — исполнения адресных зон I (направляющие линии) и II (угловые элементы);
- п. 4.1.5.1 — оформление внутренних почтовых отправлений;
- п. 6.1.2.5 — поле 40×25 мм под марку/иной знак почтовой оплаты;
- п. 6.1.2.6 — требования к линиям адресных зон;
- обязательное приложение А, рисунки А.1/А.2 и таблица А.1 — лицевая сторона внутренних конвертов без окна;
- обязательное приложение Б, рисунки Б.1/Б.2 и таблица Б.1 — внутренние конверты с окном;
- обязательное приложение Д — кодовые штампы.

## Важное следствие

Формат конверта нельзя надёжно определить только по отношению сторон фотографии.

DL имеет отношение сторон около 2:1, но C6, C5, C4 и B4 имеют очень близкие отношения сторон. Поэтому алгоритм обязан возвращать несколько кандидатов и выбирать формат по совокупности стандартных признаков после перспективного выравнивания.

## Система координат

После обнаружения четырёх углов лицевой стороны выполняется perspective rectification. Далее изображение переводится в систему координат ГОСТ:

- начало — левый верхний угол лицевой стороны;
- X — вправо;
- Y — вниз;
- размеры — в миллиметрах выбранного формата.

После определения формата любой ROI задаётся в миллиметрах и только на последнем шаге переводится в пиксели.

Это позволяет не хранить отдельные «магические» pixel coordinates для разных разрешений камеры.

## Pipeline Stage 2.1

```text
фотография
   │
   ▼
поиск внешнего прямоугольника конверта
   │
   ▼
perspective rectification
   │
   ▼
кандидаты формата по H/L
   │
   ▼
сопоставление со стандартными элементами ГОСТ
   ├─ поле марки 40×25 мм
   ├─ кодовый штамп
   ├─ направляющие линии / угловые элементы
   └─ окно, если оно присутствует
   │
   ▼
format + layout variant + confidence
   │
   ▼
миллиметровая система координат
   │
   ├─ recipient_address ROI
   ├─ recipient_postcode ROI
   ├─ sender_address ROI
   ├─ sender_postcode ROI
   └─ служебные/исключаемые зоны
   │
   ▼
OCR только необходимых ROI
```

## Поддерживаемые профили

Первый инкремент Stage 2.1 должен поддерживать внутренние отправления:

1. без окна, исполнение I — рисунок А.1;
2. без окна, исполнение II — рисунок А.2;
3. затем с окном — приложение Б.

Международные и авиационные варианты добавляются после стабилизации внутреннего профиля.

## Определение формата

Этап 1 — отношение сторон. Оно используется только как предварительный фильтр.

Этап 2 — template scoring. Для каждого кандидата строится проекция стандартных элементов в нормализованную фотографию и оценивается совпадение:

- края/линии;
- положение поля марки;
- кодовый штамп;
- направляющие линии адресной зоны;
- окно.

Результат должен иметь вид:

```json
{
  "standard": "ГОСТ Р 51506-99",
  "format": "C6",
  "layout": "I",
  "window": false,
  "confidence": 0.94
}
```

Если два профиля имеют близкий score, сервис не должен «угадывать»: возвращается список кандидатов или `layout_status=ambiguous`.

## Обрезанный адресный бланк

Ранее использованный тестовый crop с полями «Получатель / Телефон / Адрес / Индекс» не соответствует лицевой стороне конверта, изображённой в приложениях А/Б ГОСТ Р 51506-99.

Поэтому ГОСТ-сегментация применяется к полной фотографии лицевой стороны конверта. Если на вход подан уже вырезанный нестандартный адресный бланк, требуется отдельный режим `form_crop` либо явно заданный ROI. Нельзя искусственно натягивать координаты приложения А на такой crop.

## Требования к реализации

- никаких приблизительных координат зон «на глаз»;
- числовые размеры ROI должны иметь ссылку на конкретный рисунок/таблицу ГОСТ в комментарии к профилю;
- размеры хранятся в мм, а не пикселях;
- перспектива должна исправляться до сегментации;
- формат и вариант оформления должны сопровождаться confidence;
- при недостаточном confidence возвращается `unknown/ambiguous`, а не произвольный профиль;
- фотографии, не похожие на стандартный конверт, уходят в fallback pipeline.
