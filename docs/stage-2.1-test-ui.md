# Stage 2.1 — web-интерфейс тестирования

Для ручной проверки layout pipeline добавлен встроенный web-интерфейс:

```text
http://<host>:8090/test-ui
```

Он предназначен для разработки и приёмочных тестов Stage 2.1 и работает в том же контейнере `toolocr-ocr`.

## Возможности

- загрузка одного или нескольких изображений через drag&drop либо диалог выбора файлов;
- постоянное хранение исходных тестовых изображений в Docker named volume `toolocr_testdata`;
- создание папок для разных тестовых пачек писем;
- переименование и удаление тестовых папок;
- фильтрация библиотеки по папке;
- загрузка новых изображений сразу в выбранную папку;
- перемещение уже загруженных изображений между папками;
- выбор одного или нескольких ранее загруженных изображений;
- выбор режима определения формата `AUTO / SESSION / FIXED`;
- выбор ожидаемого формата `C6 / DL / C5 / C4 / B4` для SESSION/FIXED;
- запуск полного `/v1/layout/analyze` для выбранного набора;
- краткая таблица результатов: файл, папка, режим формата, layout-статус, формат/ошибка, ориентация, normalization, total_ms;
- сводная статистика последнего прогона: количество файлов, успешные/ошибки, число определённых форматов и ориентаций, среднее/median/P95 времени;
- распределение результатов по форматам, проверке формата, ориентациям, layout-статусам и normalization-статусам;
- просмотр исходного изображения по кнопке `Исходное`;
- просмотр полного JSON результата по кнопке `Показать debug` с подсветкой синтаксиса JSON;
- выгрузка одним файлом debug JSON по всем изображениям последнего прогона;
- просмотр normalized crop по кнопке `Normalized crop`;
- удаление выбранных исходных тестовых изображений из постоянного volume.

## Тестовые папки

Папка в test UI — это логическая группа изображений внутри постоянного тестового volume. Физические JPEG/PNG/TIFF-файлы по-прежнему сохраняются по внутреннему UUID, а принадлежность к папке хранится в JSON-sidecar изображения.

Есть системная группа:

```text
Без папки
```

Старые изображения, созданные до появления папок, автоматически отображаются в этой группе и не требуют миграции.

При удалении папки сами изображения **не удаляются**. Их `folder_id` сбрасывается, после чего они появляются в `Без папки`. Для физического удаления файлов используется отдельная кнопка `Удалить выбранные`.

В интерфейсе можно:

```text
создать папку
переименовать папку
удалить папку
выбрать папку как фильтр библиотеки
выбрать папку назначения при загрузке
переместить выбранные изображения в другую папку
```

Кнопка `Выбрать все` выбирает все изображения, которые видимы в текущем фильтре папки. Это позволяет быстро запустить тест на одной пачке целиком.

Список папок хранится в:

```text
/app/test-data/folders.json
```

и находится в том же Docker volume, что и изображения.

## Режимы определения формата

Перед каждым запуском выбирается режим:

```text
AUTO
SESSION
FIXED
```

`AUTO` не требует ожидаемого формата и запускает обычное автоматическое определение.

`SESSION` требует `expected_format` и использует его как сильный constraint с sanity-check. В таблице результатов отображается `confirmed`, `plausible` либо `mismatch`. `mismatch` выделяется как ошибка проверки формата.

`FIXED` требует `expected_format` и жёстко принимает его; диагностические противоречия сохраняются в debug как warnings.

Подробная семантика описана в `docs/stage-2.1-format-modes.md`.

## Статистика последнего прогона

Статистика вычисляется в браузере из ответа `POST /v1/test-ui/run` и не требует отдельного backend endpoint.

В верхней части блока результатов отображаются:

```text
Всего
Успешно
Ошибки
Формат определён
Ориентация определена
Среднее, ms
Median, ms
P95, ms
```

Ниже выводятся распределения по:

```text
Форматы
Проверка формата
Ориентация
Layout
Normalization
```

`P95` считается по `timing.total_ms` только для результатов, в которых время присутствует и является числом.

## Debug JSON

Кнопка `Показать debug` показывает полный JSON результата `analyze_layout()`.

Подсветка выполняется встроенным JavaScript без внешних CDN-зависимостей:

- ключи;
- строки;
- числа;
- boolean;
- `null`.

Перед вставкой значения экранируются, поэтому debug-данные не интерпретируются как HTML.

Кнопка `Выгрузить debug JSON` активируется после запуска теста и сохраняет один файл вида:

```text
toolocr-debug-2026-08-26T08-45-00-000Z.json
```

Формат экспорта:

```json
{
  "schema": "toolocr.test-ui.debug-export.v1",
  "exported_at": "...",
  "test_started_at": "...",
  "format_mode": "session",
  "expected_format": "C5",
  "count": 20,
  "results": [
    {
      "id": "...",
      "filename": "letter.jpg",
      "folder_id": "...",
      "folder_name": "C5 2026-08-26",
      "format_mode": "session",
      "expected_format": "C5",
      "format_validation_status": "confirmed",
      "ok": true,
      "layout_status": "detected",
      "format": "C5",
      "format_status": "session_confirmed",
      "orientation_status": "resolved",
      "orientation_deg": 180,
      "normalization_status": "cropped",
      "total_ms": 180.0,
      "error": null,
      "debug": {
        "stage": "2.1"
      }
    }
  ]
}
```

В `debug` сохраняется полный ответ анализа для соответствующего изображения. Экспорт формируется полностью в браузере и не создаёт дополнительные файлы на сервере.

## Что сохраняется

Постоянно сохраняются загруженные исходные изображения, JSON-sidecar каждого изображения и список тестовых папок.

```text
/app/test-data
```

Sidecar изображения содержит в том числе:

```json
{
  "id": "...",
  "name": "letter.jpg",
  "folder_id": "..."
}
```

Для изображения без папки:

```json
{
  "folder_id": null
}
```

Каталог смонтирован как:

```yaml
- toolocr_testdata:/app/test-data
```

Поэтому пересборка и перезапуск контейнера `ocr` не удаляют библиотеку тестовых изображений и структуру папок.

## Что не сохраняется

`normalized crop` не записывается на диск. При нажатии кнопки UI повторно читает исходное изображение, выполняет `normalize_black_background()` в памяти и отдаёт JPEG с `Cache-Control: no-store`.

Результаты последнего запуска теста, выбранный `format_mode` и рассчитанная статистика также не пишутся в volume: они хранятся только в состоянии открытой страницы браузера. После обновления страницы можно снова открыть нужную папку, выбрать режим и повторить тест.

Выгруженный debug JSON создаётся браузером на рабочей станции пользователя и не сохраняется автоматически в Docker volume.

## Запуск

После обновления ветки необходимо пересобрать OCR-контейнер, так как HTML входит в Docker image:

```bash
git pull
docker compose up -d --build ocr
```

Проверка:

```bash
make ocr-health
```

После этого открыть:

```text
http://<IP-сервера>:8090/test-ui
```

Если внешний порт изменён через `TOOLOCR_OCR_PORT`, использовать соответствующий порт.

## API тестового стенда

UI использует следующие endpoints:

```text
GET    /v1/test-ui/folders
POST   /v1/test-ui/folders
POST   /v1/test-ui/folders/{id}/rename
DELETE /v1/test-ui/folders/{id}

GET  /v1/test-ui/images
POST /v1/test-ui/images
POST /v1/test-ui/images/move
POST /v1/test-ui/images/delete

POST /v1/test-ui/run

GET  /v1/test-ui/images/{id}/original
GET  /v1/test-ui/images/{id}/normalized
```

`POST /v1/test-ui/images` принимает multipart-поле `folder_id`. Если поле не передано, изображение сохраняется без папки.

`POST /v1/test-ui/images/move` принимает:

```json
{
  "ids": ["..."],
  "folder_id": "..."
}
```

Для перемещения в `Без папки` используется:

```json
{
  "ids": ["..."],
  "folder_id": null
}
```

`POST /v1/test-ui/run` принимает, кроме `ids`, режим определения формата:

```json
{
  "ids": ["..."],
  "format_mode": "session",
  "expected_format": "C5"
}
```

`POST /v1/test-ui/run` не реализует отдельный упрощённый алгоритм: backend вызывает тот же `analyze_layout()`, который используется endpoint `/v1/layout/analyze`. Поэтому консольные и web-тесты проходят через один pipeline.

## Ограничения

Тестовый UI пока не имеет аутентификации. Его следует публиковать только во внутренней сети разработки/сортировщика либо закрывать внешним reverse proxy.

По умолчанию один запуск ограничен 100 изображениями:

```text
TEST_UI_MAX_FILES_PER_RUN=100
```

Лимит одного загружаемого изображения совпадает с `OCR_MAX_UPLOAD_MB`, а ограничение числа пикселей — с `OCR_MAX_PIXELS`.
